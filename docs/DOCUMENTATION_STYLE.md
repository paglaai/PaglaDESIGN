# DOCUMENTATION_STYLE

> *Documentation is the interface between the reader and the work.*

---

# Purpose

DOCUMENTATION_STYLE defines how PaglaAI documentation looks, reads, and navigates.

Documentation is not an afterthought.

It is part of the product and part of the deliverable.

Readers should always know where they are, where they are going, and how to get back.

---

# Documentation Principles

- **Readable** — comfortable pacing over visual density
- **Predictable** — one structure, everywhere
- **Progressive** — beginner before advanced
- **Honest** — accurate before impressive
- **Searchable** — easy to find, easy to scan

---

# Structure

Every document answers one primary question.

Documentation moves from purpose to detail:

Introduction

↓

Installation

↓

Quick Start

↓

Concepts

↓

Guides

↓

Examples

↓

API

↓

FAQ

See `CONTENT_STRATEGY.md`.

---

# Typography

Documentation uses the shared typography system (`TYPOGRAPHY.md`).

- Clear heading hierarchy
- Comfortable line height
- Bounded line length
- Predictable code formatting

Dense text is never cramped.

---

# Code

Code is styled distinctly from prose.

- Monospace typeface for all code
- Consistent code blocks and inline code
- Syntax highlighting kept minimal
- Copy affordances where they help

Code is readable before it is pretty.

---

# Navigation

Readers always know where they are.

- One clear route per page
- A table of contents for long documents
- Consistent link behavior
- Related pages linked at the end

Avoid dead ends.

---

# Headings

Headings are honest.

- One accurate top-level heading per view
- Headings describe the section that follows
- No decorative headings

---

# Links

Link text describes the destination.

- Never "click here"
- Links point to where the reader wants to go
- Related context is a paragraph away, not a maze

---

# Writing

Short paragraphs.

Clear headings.

Active voice.

Concrete examples.

Simple language.

Follow `CONTENT_STRATEGY.md` and the brand voice in `BRAND.md`.

---

# Accessibility

Documentation is held to the same standard as every interface:

- Semantic markup
- Keyboard navigation
- Visible focus
- Screen-reader comprehension

See `ACCESSIBILITY.md`.

---

# Versions

Documentation reflects the system it documents.

When the system changes, the documentation changes with it.
